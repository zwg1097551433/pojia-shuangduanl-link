# 双端互联（局域网）

让手机在**同一个 WiFi** 下使用这台电脑上已破甲的 DSH。不经过任何第三方服务，走内网直连，速度最快、延迟最低。

---

## 一、前置条件

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11 |
| DSH | 桌面版已安装且**已破甲** |
| 权限 | 管理员（注册计划任务用） |
| 状态 | DeepSeek Harness 至少启动过一次 |
| 网络 | 手机与电脑同一路由器/同一网段 |

不需要 cloudflared，不需要公网 IP，不需要联网。

## 二、部署

1. 复制整个文件夹到目标电脑
2. 双击 **`一键部署.bat`**
3. 出现：

```
校验：局域网 index 200
局域网（同一 WiFi）
  http://192.168.x.x:5288/?token=yyyy
```

4. 手机连同一个 WiFi，把这条链接贴进**地址栏**

## 三、手机侧要点

- **cookie 有效 30 天**：同一地址第二次访问可以不带 token（直接把 `http://192.168.x.x:5288/` 存成书签即可）
- 电脑 IP 变了（DHCP 重新分配）→ 旧链接失效，跑 `重新取链接.bat` 看新地址
- 电脑休眠 / 关机 → 断，唤醒后任务会自动恢复
- 同一会话别两端同时发消息（写锁 `session/writer-owned`）

## 四、目录结构

```
双端互联（局域网）\
  Deploy.ps1
  一键部署.bat
  重新取链接.bat
  卸载.bat
  payload\
    dsh-purge-community-1.6.91.tgz
    agent-presets\
  phone-url.txt
```

## 五、与公网版的区别

| | 局域网版 | 公网版 |
|---|---|---|
| 需要 cloudflared | 否 | 是 |
| 手机网络 | 必须同 WiFi | 任意网络 |
| 域名/token 变动 | 只有 IP 变才变 | 每次重建隧道都变 |
| 延迟 | 内网直连，最低 | 经 Cloudflare 中继 |
| 任务 | `DSH-Phone-Web-<端口>` | 另加 `DSH-Phone-Tunnel-<端口>` |

两个包可以在同一台机器上共存（端口自动避让，任务名带端口）。

## 六、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机打不开 | 不同网段 / 路由器 AP 隔离 | 确认手机 IP 与电脑同段；关掉路由器的「AP 隔离」 |
| `401` | token 过期或链接不全 | `重新取链接.bat` |
| `502` | web 进程没了 | 看 `%USERPROFILE%\.dsh\web-5288.log` |
| 电脑重启后打不开 | 计划任务是 `AtLogOn` 触发 | 登录 Windows 后等 10 秒 |
| 端口冲突 | 上次实例没退 | 先 `卸载.bat` |

## 七、安全提醒

局域网内任何拿到这条链接的人都能操作这台电脑（该运行时无沙箱、无审批）。家里/办公室可信网络使用；公共 WiFi 建议改用公网版并配合 token 管理。

---

## 八、AI 自修复机制

和公网版同一套：脚本卡住会生成 `diagnostics\AGENT-FIX.md`——一份写给这台电脑上 DeepSeek 的执行剧本（环境事实表 + 8 步修复命令 + 成功判据）。

- 想看体检结果：`Deploy.ps1 -SelfCheck`（只读，约 6 秒）
- 手机连不上时：把 `diagnostics\AGENT-FIX.md` 拖进 DeepSeek，让它按剧本修
- 修完让它把过程写进同目录的 `AGENT-FIX-DONE.md`

局域网模式不需要 cloudflared，失败点更少，主要是这三类：`DSH_HOME` 不存在、端口被占、web 起不来（看 `%USERPROFILE%\.dsh\web-5288.log`）。
